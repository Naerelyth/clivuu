# Durable feature contracts

Read only the section relevant to your task. This companion to `AGENTS.md` records binding product and platform contracts across desktop features.

## Editing and UI

- Capture and pin editing share one implementation. Main toolbar height is 32px; size subbar controls to fit without enlarging the main bar. Main toolbar layout reserves space for the active subbar (`4px` gap + `32px` subbar) before choosing `Below` vs `Above`, stacking the subbar above the main toolbar when `Above` so opening a subbar never flips onto the selection border. Subbars are separate content-sized strips rather than full-width toolbar extensions, synchronizing their controls before measurement and keeping horizontal scrolling disabled whenever content fits the monitor viewport. Main toolbar and active subbar stay visible during annotation drawing, mosaic, erasing, and mark transforms, hiding only during capture region selection/move/resize gestures or explicit `Space` toggle.
- Group toolbar buttons with functional separators: annotations on the left, OCR/scrolling/recording in the middle, close/pin/save/copy on the right. Color pickers belong inside per-tool subbars, never as a standalone main-toolbar dot.
- Appearance (`light`, `dark`, `system`) and accent color are independent. Dark styling uses a Dracula palette; default accent color is Dracula purple (`#bd93f9`), shared by active buttons and capture selection borders, while inactive pin shadows use their configured RGBA color and active pin shadows use the current accent. Subbars, color popups, and font/width/size popups follow the same theme. Filled selected tool icons must maintain contrast in dark mode.
- Selection handles are hollow, outlined white in dark mode and black in light mode. Standard selected annotations show handles without a white bounding box; rectangular mosaic uses a fine dashed frame. Rotatable elements share a spiral rotation handle; text items use dedicated move, rotate, resize, and delete controls.
- Shape annotations unify rectangle and ellipse under one tool button with a shape toggle and fine stipple fill toggle (`fill-pattern`), whose stipple visual language is shared by Highlight (`fill-pattern` / `fill-ellipse`), Mosaic, and Eraser area toggles; `Shift` constrains squares and circles. Resizing outlined shapes keeps uniform stroke thickness without stretching outlines.
- Arrow annotations combine 11 arrow head/shaft types with 5 line styles (`Solid`, `Dash`, `Dot`, `DashDot`, `DashDotDot`), including `PlainLine` (`Filled` ignores line style), supporting both press-drag-release two-point arrows and click-to-draw multi-segment polylines (finished on Right-click, Double-click, `Enter`, tool switch, or export; `Esc` cancels uncommitted polylines). Expose per-vertex endpoint handles with direction-appropriate hover cursors while active; `Shift` constrains drawing and vertex dragging to 45-degree increments.
- Support freehand, straight rounded-end line, rectangular, and elliptical highlights (`Shift` constrains straight-line highlights to 45-degree increments and rectangular/elliptical highlights to squares and circles, matching Shapes). Committed pen, freehand highlight, mosaic, and eraser strokes keep their original width when the active brush width changes and expose no resize or move handles at any time. Non-freehand geometric marks (`Rect`, `Ellipse`, `Arrow`, geometric `Highlight`, rectangular `Mosaic`, rectangular `Eraser`) remain movable, resizable, and restyleable while active immediately after creation, but lock permanently once deselected/finalized; only `Text` and `Sequence` remain reselectable and movable afterward, even under the `Cursor` (`Ctrl+1`) tool.
- Sequence badges sit between Highlight and Mosaic (`Ctrl+6`) and share model, next-counter state, hit testing, rendering, and subbars across capture and pins. Cursor and subbar preview the next badge; hovering the preview switches among five shapes, clicking sets or resets the next index, and `Z`/`X` decrement or increment it without editing placed badges. Selecting and hovering a placed badge exposes `−`/`+` index controls, delete, and leader toggle; dragging moves its body or notched arrow / short-distance triangle leader (`Shift` snaps in display coordinates, dragging the tip inside the badge hides the leader). Placed sequence edits do not alter the next counter, and placement undo/redo restores numbering. Only `BorderedCircle` uses a separate foreground border color.
- Mosaic supports rectangular and freehand geometry with pixelation (`pixelate`) and blur (`blur`) modes switched by clicking the effect toggle button in the subbar. Geometry does not convert between rectangular and freehand marks once placed. Brush width comes first in the subbar, followed by a freehand/rectangular toggle; rectangular mosaic draws a fine preview frame.
- Mosaic width and strength operate independently: in freehand mode, canvas wheel adjusts width while the strength slider controls intensity; in rectangular mode, canvas wheel adjusts strength and updates the slider, and scrolling over the strength slider itself always steps by `1` with coalesced single-step undo. Pixelation and blur share one unified strength range (`3–24`, default `8`) preserved when toggling between modes for readability and frame-rate stability without flicker across rapid drags or strength changes.
- Width indicators and canvas cursors share display-unit conversion. Freehand cursors reflect active width and tool color; arrow crosshairs keep fixed-size arms around a center dot without an outer outline; mosaic and eraser cursors match canvas footprint and display units.
- In capture annotation mode, marks can start or extend outside the selection; expanding the selection later reveals those marks, and export crops to the final selection. In selection mode, dragging outside extends the nearest selection edges and shows directional resize cursors rather than triggering a magnifier flash.
- Show the magnifier before selecting, during initial selection drag, during boundary resizing, while hovering stationary inside the completed selection in `Cursor` (`Select`) mode (when not over floating controls, popups, OCR, or annotation targets), and during temporary `Alt` inspection; hide contextual key-tips during active selection or annotation drags or when their bounding box overlaps a confirmed selection rectangle while keeping region-history tips (`R`, `Page Up / Page Down`) in stationary hover and selection states with distinct `+` chord joiners and `/` alternative dividers; automatically hide the top-left pixel size indicator while hovered in ready state. When `capture-cursor=true` provides a clean/cursor frame pair (GNOME Mutter dual-stream session and real X11 XFixes), pressing `` ` `` or `!` during capture toggles cursor visibility in place at its real compositor position. Keep the sampled center pixel aligned with crosshair and selection intersections across fractional DPR, monitor borders, and edge drags. Toggling internal appearance or grid options takes effect immediately.
- Place and edit text directly on the canvas, never inside the subbar. Support moving, rotating, and handle/wheel resizing (`1–72` font size) while keeping the toolbar visible. Expose font family, bold/italic, outline (`none`, `auto`, `white`, `black`, `custom`), and grouped colors.
- Focused text displays a fixed neutral fine frame and rotation handle, revealing resize and delete handles on hover; existing text remains hoverable and directly editable, and the top-right badge deletes it. Tiny text frames enforce minimum handle spacing. Insertion caret, active text frame, and area-eraser preview use neutral colors rather than the accent color.
- Expand text frames live during IME preedit composition. Position font-search popups directly at the input rectangle without double coordinate offsets; `Esc` during active IME preedit clears uncommitted preedit first, and `Esc` with no active preedit closes the font panel. Keep text input working under both IBus and Fcitx.
- Font selection opens its panel directly without nested submenus. Dropdowns show clear visual affordances. Color popups present a compact square launcher swatch, 20 preset swatches, custom hex (`#RRGGBB`) plus opacity input, and color picking when supported by the session.
- Local editing shortcuts live in `desktop/src/editor/shortcuts.rs`: `Ctrl+1` Cursor, `Ctrl+2..8` annotation tools, `E` Eraser, `Ctrl+Y` redo, `Ctrl+Shift+Z` irreversible clear. Focused text fields, search entries, spin controls, popups, and active IME preedit retain text priority for plain keys (`1..9`, `E`, etc.).
- OCR shares one structured `OcrDocument` (`OcrBlock` / `OcrLine` / proportional `char_x`), `OcrSelection`, rendering layer (`ocr_layer.rs`), and compact 32px `OcrBar` across capture and pins, supporting dual local engines (`Paddle` PP-OCRv5 Mobile via `dlopen` ONNX Runtime C API v17 and `Tesseract` 5 TSV word-box fallback) without bundling `.onnx` weights or `libonnxruntime.so` inside binaries or release packages. Every recognition spawns a GUI-free single-shot worker subprocess (`clivuu worker ocr-document` / `--ocr-worker`) over `memfd_create` that exits immediately after returning that image's result so zero ONNX memory or background threads remain resident. On capture, `O` enters interactive in-place text selection (character drag confined horizontally to the anchor block, double-click line, triple-click block, `Ctrl+A`, `Ctrl+C`, `Enter` copy-and-close, `Esc` deselect-then-exit) unless `ocr-quick-copy=true`, while `Shift+O` and `-o ocr_clipboard` always quick-copy; on pins, `O` / toolbar / context-menu `Recognize text` toggles live zoom-aware canvas text selection while holding `Alt` preserves window drag anywhere over dense text.

### Settings

- Preferences run as an independent regular window destroyed on close, reopening on the General tab without persisting window geometry or scroll position, and keeping a normal taskbar identity. Vertical sidebar navigation uses per-section scrollers so switching pages avoids height flicker.
- Preferences apply light/dark Dracula theming and recolor standard GTK window controls while preserving native button shapes. Language names render as endonyms (`English`, `简体中文`), with the accent reset button aligned on the accent row. Descriptions and hints omit trailing periods in both locales and separate clauses with commas, keeping literal dots in filenames, tokens, and shortcuts.
- Section resets apply only to the visible section rather than the entire category tab. Show scope description beside section title and reset button, and require secondary confirmation without repeating the scope description in the dialog prompt. Shortcut reference pages omit reset controls.
- Save splits into Images and Recording sections with a naming-rules guide accessible from the header. Template tokens in the guide are selectable, explanatory prose is not, and opening the guide hides the insertion caret. After border resizing, restore the interior pointer cursor while keeping the text cursor over inputs.
- Control exposes grouped shortcut reference tables and customizable pin mouse gestures, with reset scoped to pin mouse gestures after confirmation. Default gesture mappings and conflict resolution belong in `core::config`.
- Pins group settings into Display, Behavior, and Conversion sections. Expose only controls backed by working implementation logic.

## Pins and paste

- `clivuu paste` and tray paste share one clipboard import path; `Ctrl+T` during interactive capture triggers the same pin flow as the toolbar Pin button. Repeating an identical source reveals and flashes the existing pin independently of `pin-flash-new`. An empty clipboard creates nothing; restoring closed pins uses tray recovery entries or `reopen-pin` / `reopen-pins`.
- Pinning the latest capture reads completed capture history (`128 MiB` memory ring) independently of clipboard state, associating the capture record with its created pin so repeated pinning reveals and flashes that pin until replaced or destroyed.
- Separate logical pin activation and shadow color from pointer hover and keyboard focus. Leaving a pin or dismissing its menu or toolbar preserves logical activation; clicking editor controls activates the owning pin. External window clicks or focus loss deactivate pins when delivered by the desktop backend. On GNOME, pins accept keyboard focus by default; `pin-gnome-focus=false` disables focus throughout the pin lifecycle so pins deactivate on pointer leave unless an editor, menu, or drag owns them, preserving dash-to-panel visibility without remapping surfaces on toolbar toggles. Layer-shell pins keep `ON_DEMAND`. Pin Crop renders a hardcoded `1px` accent frame with playback-aligned circular outer anchors in unscaled logical coordinates, supporting immediate full-frame edge/corner resize, interior move and 8-way resize of an active sub-crop, and in-place desktop coordinate preservation on Apply; crop handles appear only while Crop is active and vanish when switching tools.
- CLI, tray, pin replacement (`Ctrl+V`), and drag-and-drop share one MIME and import pipeline recognizing images, file paths/URIs, HTML, plain text, and hex/RGB color values (converting valid standalone color strings such as `#ffffff` to color cards).
- Keep full physical bitmap resolution for raster pins; select target surface density before rasterizing logical text and color cards. Monitor DPR changes re-render without altering identity. Display, editing, copying, and saving always read full-resolution source data.
- Re-revealing a matching source preserves existing annotations on that pin. Retain original source text for `Ctrl+Shift+C`. `Ctrl+V` replaces content on the same pin identity and position. Multi-pin export (`Ctrl+A` then copy/save) snapshots the batch layout and origin at trigger time to prevent async clipboard races.
- Display filters (`1`/`2` rotate, `3`/`4` flip, `5` grayscale, `6` invert) remain reversible and consistent between canvas and export without double-applying filters to stored sources. Closing a pin supports recovery (up to `pin-closed-limit`, default `1`); destroying deletes permanently. New pins start logically active without flashing by default, with cursor-centered wheel zoom off and smooth scaling on.
- Modifier-based pin mouse gestures require keyboard focus from the compositor. On GNOME, enabling `pin-gnome-focus` provides reliable modifier state during pin interaction without querying Shell internals.
- Pin scale and opacity feedback shares one presentation path across wheel events, keyboard shortcuts, border drags, and menu controls, displaying percentages in the top-left corner for 1000 ms after the final adjustment while excluding overlays from exports, persistence, and hit regions. Updating an open menu refreshes its opacity label in place without rebuilding the menu.
- Thumbnail toggle/restore, flash animations, group switches, flash-time paste hiding, drop preservation, and confirmation prompts live in shared pin controller logic rather than per-widget copies.
- Pin groups preserve a non-removable canonical `"default"` group alongside up to 63 custom groups with optional `#rrggbb` color tags. Expose group switching (with active group name in the header), creation, and cleanup in the tray `Pin groups` submenu, batch recovery/cleanup in the tray `Pin recovery & cleanup` submenu, state-aware visibility for recording and click-through items, single/multi-pin `Move to group` (and `Move to new group...`) inside the pin context menu without opening extra X11 popup surfaces, and independent native Wayland windows (`--group-manager`) for `show-group-manager`, `create-group --prompt`, and `switch-groups`. Deleting a custom group supports migrating its pins to another group or removing them directly.

## Scrolling capture and recording

- Capture toolbar Scrolling and `clivuu scroll` enter the same `start_scroll()` -> `scrolling::run()` pipeline with identical stitching, preview, and export paths. Tray exposes capture, window capture, recording, and paste workflows distinct from capture-toolbar scrolling.
- Reuse the capture selection frame and common draggable toolbar for scrolling and recording setup. Scrolling adds an explicit move-region button and has no pause state.
- Moving the scrolling region locks to the active scroll axis while preserving capture dimensions and keeping a normal arrow cursor across hover and drag. A manually positioned toolbar follows region displacement while keeping its relative offset. Axis toggle (`Vertical` / `Horizontal`) and move-region remain separate controls.
- Pause frame sampling while dragging the toolbar or moving the region, resuming automatically once settled. Region adjustments must preserve navigation, coverage tracking, and exportable output.
- Position the live preview strip outside the capture rect when space allows, hiding it on cramped displays. Preview texture refreshes must not shift layout or bleed into captured frames. Exclude Clivuu overlays, borders, and shadows without flickering visible controls, separating paint transparency from pointer hit-testing.
- Keep body stitch matching, multi-layer foreground/background matching, fixed header/footer margin isolation, coverage tracking, manual trim (`Trim above/below` or `Trim left/right of current view`), and optional reverse-scroll auto-crop (`scroll-auto-crop`, default `false`) independent across reverse scrolling, revisits, and repetitive grids. Stationary frames with minor edge scrollbar fade or localized UI blink resolve to `shift = 0` without relaxing periodic ambiguity checks. The green viewport rectangle in the preview tracks true document coordinates without fabricating dimensions.
- Always keep committed reliable content exportable on stop, cancellation, frame source loss, or terminal match failures. Expose in-session mismatch recovery via `Reset scrolling capture` (`Continue from current view` to re-anchor matching while retaining stitched frames, and `Restart in current region` / `Ctrl+R` to clear and re-sample in place). Only patch verified occlusion gaps rather than relaxing stitch thresholds into corrupted output; surface clear status feedback on errors.
- Request `RemoteDesktop` scroll permission only for explicit Auto-scroll, deriving closed-loop proportional smooth pulses without synthetic `axis_stop` flings (`150–5000 ms` clamped runtime, `300–3000 ms` preference range), exiting without mismatch errors when reaching the scroll boundary or stopping manually, and pausing automatically when the real cursor leaves the capture rect or enters the toolbar, hint, or preview. Unsupported auto-scroll never blocks manual scrolling.
- Stream recording acquisition through bounded intermediate buffers (`vp9` lossless `cq-level=0` Y444 Matroska plus independent 48 kHz stereo `flac` tracks). Memory-first storage enforces `recording-temp-limit-mib` strictly against acquisition frames and stops capture upon reaching the cap without silent spillover; export scratch uses destination-volume space checks independently of the acquisition ceiling. Stop, restart, and exit finalize tracks before publishing, preserving recovery data on export errors without leaking internal temporary paths in UI copy.
- Releasing the drag for tray-started recording jumps straight to Ready controls (`FPS`, `Delay`, `Normal`/`Quick` mode, cursor toggle, and system/microphone toggles defaulted on when detected). Audio device discovery runs through platform adapters, system/mic streams sync to the video clock across pause/resume, input selections lock when recording begins, and `GIF` export omits audio without discarding source tracks. Test media paths with isolated virtual devices only.
- Recording keeps the live selection frame and draggable toolbar. Pause excludes paused wall clock time from both timeline duration and encoded timestamps. Confirm Restart and Discard before deleting private intermediate bytes. Hide painted controls overlapping the capture rect during active recording while keeping tray actions and D-Bus commands functional.
- Cancelling recording during setup, countdown, picker dismissal, or explicit discard completes without error notifications; report real acquisition, encoder, or export errors normally.
- Crop negotiated source pixels before YUV conversion rather than downscaling frames to logical display size. Every export format (`MP4`, `WebM`, `GIF`) reads the exact lossless intermediate source and runs through one export and native GTK save chooser lifecycle.
- Stopping Normal recording opens the frameless playback editor at the captured region with seek/trim handles, live canvas edge/corner crop, `0.2–2.0x` playback speeds, per-track `0–200%` gain and mute, and unified export (`MP4`, `WebM`, `GIF`). Quick mode writes MP4 directly after stop. Explicit CLI output paths determine direct format when given; successful, cancelled, and failed exports preserve editable material until explicit discard or close cleanup.

## Config, saving and notifications

- GUI and CLI share one configuration schema and grouped sparse XDG INI storage. Image and video filename templates share token parsing, validation, and preview (`$yyyy$`, `$MM$`, `$dd$`, `$HH$`, `$mm$`, `$ss$`, `$uuid$`, `$unix$`, `$unix_ms$`, `%os%`, `%computername%`, `%username%`, English weekday/month names, nested relative subdirectories such as `$yyyy$/$MM$/`, rejecting path-escaping templates).
- Image saving supports manual, quick, and automatic save modes; video recording supports manual and quick modes. Default quick directories resolve to `Pictures/Clivuu` and `Videos/Clivuu` (with fallback paths when XDG dirs are unavailable). Create missing directories automatically, number filename collisions in quick/automatic modes instead of overwriting, and skip automatic copies when cancelled.
- Manual save uses a single Clivuu-managed GTK file dialog (native Wayland on Wayland sessions) rather than FileChooser portal dialogs, updating suffixes live inside the open dialog without reopen cycles.
- Type choices display clean image/video format names (`PNG`, `JPEG`, `MP4`, `WebM`, `GIF`). `JPEG` defaults to `.jpg` while preserving user-entered `.jpeg`, and final file extensions always match actual encoded bytes without altering approved paths behind overwrite confirmation. PNG always uses fast lossless encoding, while JPEG uses `image-quality` (`0–100`, default `100`, with `0` mapped to `1`).
- `core::image::export` owns format validation, extension mapping, quality mapping, and encoding across CLI, capture, pins, scrolling, and playback/save paths.
- Notifications deliver observable quick-save and error feedback using Clivuu launcher identity and icon. Saved-image notifications attach the saved thumbnail; video and status notifications avoid oversized content icons and rely on desktop notification rendering.
- Clivuu owns translations for the `Show in Files` notification action chosen from system locale independently of the UI override (`en` fallback). Reveal saved files over D-Bus `org.freedesktop.FileManager1`, falling back to the default directory handler without hardcoding a specific file manager.

## Identity, startup and packaging

- Authorization requests use native desktop portals with launcher identity preserved. Denying permission leaves a valid path to request access again without building custom consent dialogs or editing system permissions behind the user's back. Accepted first-time requests must trigger at most one capture and shutter sound.
- Canonical desktop and icon theme identity is `io.github.naerelyth.clivuu`. Resolve renamed launchers through standard Desktop Entry metadata while keeping D-Bus service name `io.github.naerelyth.Clivuu.Desktop` stable.
- Application icons live in `assets/icons/`: launcher `clivoo.svg` and tray `clivoo-transparent.svg`. Notifications prefer the installed icon theme entry and fall back to bundled SVG assets.
- Restart, autostart, and identity resolution work uniformly across native DEB/RPM/TGZ packages and AppImage builds via standard XDG metadata and `APPIMAGE` detection, never dropping action arguments into restart loops or hardcoding a single prefix.
- Tray exposes Restart; Preferences -> General controls autostart (default off), writing standard XDG Autostart entries directly rather than duplicating state in INI or modifying window manager configs.
- Restart halts new inputs, cancels active dialogs/captures/imports, finalizes open recordings, flushes config and pin state, and releases single-instance IPC before spawning the replacement process; persistence failure leaves the live service running. Separate Preferences and Save window processes never register duplicate tray icons or D-Bus services.
- Tray-triggered acquisition replies to the D-Bus menu activation and waits briefly for popup dismissal before grabbing frames, isolating that delay strictly within tray integration.
- Cargo builds the `clivuu` CLI and `clivuu-desktop` GUI binaries; CMake/CPack handles prefix installation and DEB/RPM/TGZ/AppImage packaging without Python packaging wrappers. Releases bundle the verified ELF pair, current icons, and bilingual docs, keeping test extensions and fixtures outside release payloads while preserving existing user data on upgrade.
